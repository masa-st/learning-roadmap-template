# ロードマップ新規作成（create-roadmap）

このスキルは、新しい分野の学習ロードマップ（`<分野ディレクトリ>/ROADMAP.md`）を、
ユーザーへのヒアリングを通じて対話的に作成するための手続きです。

**フォーマットの正は `templates/ROADMAP_TEMPLATE.md`、運用ルールの正は `CLAUDE.md` です。**
このスキル側には構成・記法ルールを再掲しません。実行前に次の 2 つを確認してください
（会話に既に入っていれば読み直し不要）。

- `templates/ROADMAP_TEMPLATE.md` — ロードマップの章構成・進捗表・学習メモの雛形
- `CLAUDE.md` の「Markdown に数式を書くときのルール」「分野をまたぐ相互参照の扱い」

記入済みの実例が見たい場合は、既存の分野ディレクトリの `ROADMAP.md`
（例: `statistics-certificate-pre1/ROADMAP.md`）を参考にしてよい。

## 手順

### 1. ヒアリング

以下を対話で確認する。**一度に全部質問せず**、会話の流れに沿って 1〜2 項目ずつ聞く。
ユーザーが最初のメッセージで既に答えている項目は聞き直さない。

1. **学びたい分野** — 何を学びたいか。範囲が広すぎる場合（「数学」「機械学習全般」など）は、
   どこに関心の中心があるかを掘り下げて、1 つのロードマップとして成立する粒度に絞り込む。
2. **学ぶ動機・目指す方向性** — なぜ学ぶのか。資格・試験の合格、業務や研究への応用、
   別分野を学ぶための前提固め、教養・興味など。
   これは「学習目標」欄の書きぶりと、章立ての取捨選択・到達目標の粒度を決める最重要の材料。
   試験合格が目的なら出題範囲が章立ての骨格になり、応用が目的なら応用先から逆算する。
3. **現在の知識レベル・前提知識** — どこまで学習済みか。学歴・職歴上の背景、読んだことのある
   教科書、取得済みの資格、隣接分野の経験などを手がかりにする。
   自己申告が曖昧な場合は、その分野の基本的な概念をいくつか挙げて「これは説明できそうか」と
   確認するとよい。ここで測った水準が①（最初の章）の内容を決める。
4. **学習スタイル・使える時間**（補足） — 通勤中などのスキマ時間中心か、腰を据えて
   机に向かえるか。スキマ時間中心なら、長い手計算・証明は「宿題」として後日に回す運用
   （`CLAUDE.md` の宿題の節）が効くので、その旨をロードマップの学習目標の下に一言添えてよい。

### 2. 章立てドラフトの提案

本文を書き始める前に、まず**骨格だけ**を提示して合意を取る。

- 全体ロードマップ（①→②→… の流れ図）と、各章の一言説明を会話で提示する。
- 章の数は 5〜12 程度を目安にする。1 章が 1〜数回のセッションで区切りがつく粒度にする。
- 学習順の注記（前倒ししてよい章、独立性が高く後回しにできる章、最短経路など）も
  この段階で提案する。
- ユーザーのフィードバックを受けて章立てを直し、合意してから次へ進む。

### 3. ROADMAP.md の生成

- 分野ディレクトリ名は**英語ケバブケース**（例: `information-geometry`,
  `statistics-certificate-pre1`）で提案し、ユーザーに確認してから作る。
- `templates/ROADMAP_TEMPLATE.md` の構成に従い、`<分野ディレクトリ>/ROADMAP.md` を書く。
  - 「学習目標」はヒアリング 2.（動機・方向性）を反映し、「最終的に何ができるようになるか」を
    具体的な箇条書きにする。
  - 各章の「学ぶ内容」は、ヒアリング 3.（現在の知識レベル）を反映して深さを調整する。
    既に知っている内容は章として立てず、必要なら①を「補強」の章にする。
  - 進捗表は全章分の行を作り、理解度・完了日・メモは空欄で置く。
  - 学習メモの各欄は見出しだけ作り、「次回学ぶ内容」に最初のセッションで始めるべき項目を
    1 行入れておく。
  - 数式を書く場合は `CLAUDE.md` の「Markdown に数式を書くときのルール」に厳密に従う。

### 4. 相互参照の接続（既存分野がある場合のみ）

- 新しいロードマップの章が既存分野の `ROADMAP.md` と内容的に重なる場合、
  「同じ内容を二重に学ばない」ための相互参照を新ロードマップ側に書く
  （書き方はテンプレートおよび既存ロードマップの冒頭の相互参照リストを参照）。
- 参照先の章をユーザーが**既に学習済み**の場合は、`CLAUDE.md` の
  「分野をまたぐ相互参照の扱い」に従い、既存分野の進捗表のメモ欄への追記が必要かを確認する。

### 5. README の更新

- `README.md` の分野一覧に、新しい分野ディレクトリへのリンクと一言説明
  （目指す方向性が分かるもの）を追記する。

### 6. commit・push

- 内容をユーザーに確認してもらってから commit する。コミットメッセージは分野が分かるように書く
  （例: `add roadmap: 統計検定準1級の学習ロードマップを作成`）。
- 現在のブランチに push したら完了。デフォルトブランチへのマージは Stop フックが自動で行う
  （`CLAUDE.md` の「Git運用」参照）。
- そのまま学習を始める場合は、作成したロードマップの①から通常のセッションとして進めてよい。

## 注意

- ロードマップは「進捗と再開のための記録」であり教科書ではない。各章の「学ぶ内容」は
  トピックの箇条書きにとどめ、解説本文を書き込まない（解説は会話の中で行う）。
- 章立て・到達目標は一度作ったら固定ではないが、大きな変更はユーザーとの合意が必要
  （`CLAUDE.md` の「注意事項」参照）。作成時点で完璧を目指しすぎず、
  学習が進んでから調整する前提でよい。
