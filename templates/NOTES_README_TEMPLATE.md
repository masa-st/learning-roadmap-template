# ＜ディレクトリのテーマ＞ ノート

<!-- 何を相談し、何を溜める場所かを 2〜3 行で。学習ロードマップとの違いが分かるように。 -->

学習ロードマップとは別に、**＜例: 実務のエンジニアリング上の課題＞** を相談し、
そこで出てきた知見を蓄積していく場所。

## 運用方針

- **ロードマップは定めない。** 分野ディレクトリと違い、体系的なカリキュラムを追うのではなく、
  実際に困ったことを起点にする。したがって `ROADMAP.md` は置かない。
- 1 テーマ 1 ファイル。`notes/NN-slug.md` に置き、この README を索引とする。
- 各ノートは次の構成を基本にする（テーマによって増減してよい）。
  1. **相談したこと** — どういう状況で何に困っていたか。後から読んだときに文脈が復元できるように。
  2. **結論** — 数行で。
  3. **本文** — 判断の理由、具体的な設計、コード断片など。
  4. **未解決・宿題** — その場で決めきれなかったこと、後日試すこと。
- 「なぜそうするのか」を必ず残す。手順だけ書いても、状況が変わったときに応用が効かないため。
- 採用しなかった選択肢とその理由も、分かる範囲で書き残す。後から「なぜこうしなかったのか」を
  思い出せるようにするため。
- 数式を書く場合は、リポジトリ直下の `CLAUDE.md` の「Markdown に数式を書くときのルール」に従う
  （インラインは `$...$`、ディスプレイは math フェンス、`$$` は使わない）。
