# Side Notes（＜分野名＞ネタ帳）

<!--
  何を溜める場所かを 2〜4 行で。ROADMAP.md の本流（正統カリキュラムの進捗・メモ）との
  違いが分かるように書く。例:
  - 試験で使える計算テクニック・覚え方
  - 用語・概念の区別（似た言葉が別物、同じことの別名）
  - 章をまたぐつながり（ある章の道具が別の章で再登場する構図）
  - 本流から逸れた周辺分野の話題
  「溜まったら勉強会の発表ネタにする」のような使い道があれば、それも書いておく。
-->

`ROADMAP.md` の本流（正統カリキュラムの進捗・メモ）とは別に、以下のようなネタを溜めておく場所。

- **＜ネタの種類 1＞**: ＜説明＞
- **＜ネタの種類 2＞**: ＜説明＞

## 書き方の方針

<!--
  以下は作成元リポジトリの複数分野で共通していた方針。分野に合わせて足し引きしてよいが、
  数式ルールの項だけは CLAUDE.md の定めなので削らない。
-->

- 1 ネタ 1 ファイル。ファイル名は `NN-slug.md`（`NN` は 2 桁の連番、`slug` は英語ケバブケース）。
- 各ファイルの冒頭に **タグ**（例: `試験で使える` / `小ネタ` / `用語整理` / `分野横断` / `宿題あり`）と
  **一言サマリ** を書く。索引のこの表と同じ内容にする。
- ロードマップ本体との関係（どの章の脱線か、なぜ本体に入れないのか）を明記しておくと、
  後で「本体に昇格すべきか」を判断しやすい。
- 「進捗と再開のための記録」であり、講義ノートの丸写しはしない。要点と、後で会話を
  再開するのに必要な取っ掛かりを残す。
- 数式は GitHub のプレビューで正しく表示されることを最優先にする。
  インラインは `$...$`、ディスプレイは math フェンス（バッククォート 3 つ + `math`）を使い、
  `$$` は使わない。詳細はリポジトリ直下の `CLAUDE.md` の
  「Markdown に数式を書くときのルール」を参照。
- 宿題が出たネタは、そのファイル内に「宿題」の節を設けて書き、索引の一言に **宿題あり** と記す。
